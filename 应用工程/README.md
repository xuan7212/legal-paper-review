# 法学论衡 · 法学论文审查助手

面向法学本科生与硕士生的论文初稿自查工作台，帮助作者在提交导师前发现论证缺口、推敲表达，并追踪修改结果。当前交付版本为 **v0.2.0**。

采用 React、TypeScript、Vite、Tailwind CSS、Fastify 和 DeepSeek。支持论文输入与文件解析、研究问题确认、逻辑与表达审查、逐段修改、多轮复查、材料和反馈、历史报告复制及下载。

## 项目评审与演示

启动后，从侧栏的“项目说明”了解用户、使用场景、交付范围与验证计划。主页点击“体验示例演示”，可直接进入预设教学样本，体验 4 条论证问题与 1 条表达建议。

建议按以下顺序演示。

1. 打开“三份判决难以支撑普遍性结论”，查看原文定位、判断依据和修改方向。
2. 点击“替换原句”，查看工作副本更新提示，并提交作者反馈。
3. 点击“修改后复查”，对照处理结果，切换第 1 轮与第 2 轮查看历史快照。
4. 打开“复制报告”，下载包含已审查结果及当前工作副本的文本报告。
5. 新建审查，在设置中配置有效 DeepSeek API Key，进入真实论文的提取、确认、审查与复查流程。

示例使用预设审查内容及固定复查规则，页面与导出报告均保留演示来源。任意自定义修改会标记为需重新判断，预设参考句替换按示例规则显示处理结果。演示过程直接使用本地样本。

## 产品价值与验证状态

核心检查概念混用、论据与结论脱节、前后矛盾和分析层次混淆，辅以歧义、指代、长句及法律术语检查。每条建议包含原文定位、判断依据、修改方向及需要补充的材料。学术争议与外部材料分别保留核对状态。

真实模型接口及受控审查流程已实现。模型质量、当前账户的模型权限与真实调用成本，需要有效密钥及法学评审样本验证。查重率与 AI 率入口标注为待接入。

已确认可以招募约 30—40 位本科与硕士用户。计划先访谈 8 人，再邀请 10—12 人使用授权初稿片段试用。比较同一模型的通用提示词与垂直流程，分别记录专业评审确认的问题准确率、预标注问题发现率、修改时间及再次使用情况。上述人数为验证计划，访谈结果和模型效果数据待采集。

后续将真实失败案例整理为专项 Skill，包含适用条件、检查步骤、参考材料、正反例和回归测试，用固定样本比较迭代前后的质量、时间与成本。

## 本地启动

macOS 可直接双击本目录中的 [启动法学论衡.command](启动法学论衡.command)。已有服务会直接打开；首次启动会在依赖安装完成的情况下生成构建文件。请保留启动窗口，使用结束后按 Control+C 停止本次启动的服务。

`apps/web/index.html` 与 `dist/client/index.html` 通过本地服务加载应用。直接双击 HTML 时会显示启动说明；服务就绪后可点击说明页中的“打开法学论衡”进入工作台。

以下命令在“应用工程”目录内执行。从项目根目录进入时，先运行 `cd 应用工程`。

准备 Node.js 22.13 及以上版本，以及 pnpm 11.25。旧版 Word 解析需要 LibreOffice，其 `soffice` 命令应在 PATH 中，也可通过 `SOFFICE_BIN` 指定可执行文件。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

浏览器打开 http://127.0.0.1:5173。在“设置 → 模型与 API 配置”中输入自己的 DeepSeek API Key，选择模型并测试连接，然后载入示例或上传自己的片段开始审查。

```sh
pnpm build
pnpm start
```

生产构建由 Fastify 同时提供页面与 API，默认地址为 http://127.0.0.1:3001。可通过 `HOST`、`PORT` 配置监听地址，通过 `PUBLIC_ORIGIN` 指定公开站点的完整来源。公开部署时使用同域 HTTPS 反向代理，并为 LibreOffice 转换进程提供受限运行环境。

## 使用与数据处理

- 论文片段按去除空白字符后的 UTF-16 长度计数，范围为 1500—5000 字，单个上传文件最大 20 MB。
- TXT、MD、DOCX 和文字型 PDF 读取真实内容，旧版 DOC 通过独立 LibreOffice 进程转换。解析后请核对 PDF 的文字顺序，扫描版 PDF 需要先进行 OCR。
- 提取与审查之间需要作者确认研究问题和观点。审查包含模型回读与原文校验，修改后按上一轮问题进行复查。
- 同一会话中可切换历史轮次并复制或下载报告。最新报告附录保留当前工作副本文本、材料与反馈，标明尚待复查的修改。
- 正文、确认依据、背景问题、提纲、引用材料或作者反馈的修改均可触发复查。历史报告保留相应轮次的独立快照。
- 密钥保存在后端会话内存，成功测试后有效 2 小时。新建审查保留模型配置，清除密钥保留已完成结果。
- 浏览器刷新或关闭后创建新会话，离开页面时尝试清理服务端数据，遗留会话在最后有效操作后 2 小时清理。进程重启后内存数据释放。
- 真实模型调用需要有效的自带密钥，并使用对应 DeepSeek 账户的额度。
- 查重率和 AI 率提供独立的待接入入口，供应商确认后接入实际检测报告。法律资料核验显示所需材料与人工核对状态。

## 验证

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e
```

`pnpm test` 包含业务、接口、组件、模型适配、文件解析测试及原有 Python 文档检查。旧版 DOC 转换测试需要 LibreOffice，Python 文档检查与测试文件生成需要 Python 3。

端到端测试默认使用已安装的 Chrome。也可先执行 `pnpm exec playwright install chromium`，再使用 `PLAYWRIGHT_CHANNEL=chromium pnpm test:e2e`。测试入口仅监听本机，注入固定响应替身，覆盖模型配置、完整审查、演示与真实模式隔离、报告下载、移动端上传，以及 320 / 390 / 768 / 1024 像素宽度的布局。正式审查入口调用 DeepSeek 服务。

模型输出质量与两个模型的实际账户权限，需要使用有效密钥和法学评审样本单独联调。80% 准确率作为产品内部评估目标，由实际试用统计。
